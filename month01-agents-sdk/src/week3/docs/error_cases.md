## 案例详情

### 案例 1: 检测逻辑缺陷导致误判

**发现日期**: 2026-04-20

**问题**: 一致性测试显示 70% 一致率，但实际 Agent 行为可能更稳定

**现象**:
```
问题："帮我查一下订单 ORD20260417001 的状态"

Run 1: extract_tool() → "unknown"
Run 2: extract_tool() → "direct_response"
Run 3: extract_tool() → "direct_response"
Run 4: extract_tool() → "direct_response"
Run 5: extract_tool() → "unknown"
```

**实际输出** (5 次都包含订单详情):
```
📦 订单详情
━━━━━━━━━━━━━━━━
订单号：ORD20260417001
商品：iPhone 15 Pro
金额：¥7,999.00
状态：已发货
物流：顺丰 SF1234567890
━━━━━━━━━━━━━━━━
```

**原因分析**:
1. `extract_tool()` 函数只匹配简单的关键词（如 "📦 订单详情"）
2. Agent 输出格式有变化（有时用 `**订单号**`，有时用 `订单号：`）
3. 实际上 Agent 每次都正确调用了 `query_order_status` tool

**修复方案**:
1. 改进 `extract_tool()` 逻辑，使用更灵活的正则匹配
2. 或者直接分析 trace 数据（需要设置 OPENAI_API_KEY）
3. 最佳方案：使用官方的 `get_trace()` 函数

**教训**:
> 不能仅凭输出文本判断 tool 调用，需要分析 trace！

## 错误分类定义

### Prompt 问题
Agent 不理解该不该调用 tool，表现为：
- 该调用 tool 时直接回复
- 不该调用 tool 时误调用

### Schema 问题
Agent 选对了 tool 但参数错了，表现为：
- 参数格式错误
- 参数值提取错误
- 缺少必要参数

### 其他
- 模型随机性导致的输出差异
- 网络问题导致的超时
- 检测逻辑缺陷
