# RAG 系统架构概述

## 什么是 RAG

RAG (Retrieval-Augmented Generation) 是一种结合信息检索和文本生成的技术架构。
它在 LLM 生成回答之前，先从外部知识库检索相关信息，作为上下文增强生成质量。

## 核心流程

```
用户查询 → Embedding → 向量检索 → 相关文档 → Prompt 组装 → LLM 生成 → 回答
```

### 1. Indexing 阶段（离线）
- 加载文档
- 文本分块
- 生成 Embedding
- 存入向量数据库

### 2. Retrieval 阶段（在线）
- 查询 Embedding
- 向量相似度搜索
- 返回 Top-K 相关片段

### 3. Generation 阶段
- 组装 Prompt（检索结果 + 用户问题）
- LLM 生成回答
- 返回给用户

## 进阶技术

### Hybrid Search（混合检索）
结合向量检索（语义）和关键词检索（精确）：
- 向量检索：捕获语义相似性
- BM25：捕获关键词匹配
- RRF 融合：无监督排序融合

### Query Rewriting（查询改写）
- 关键词提取
- 同义词扩展
- 子问题拆解
- 多轮对话上下文补充

### Reranking
检索后用更强的模型对结果重新排序，提高精度。

## 评估指标

| 指标 | 含义 |
|------|------|
| Hit Rate | 前 K 个结果中是否包含正确答案 |
| MRR | 第一个正确答案的平均倒数排名 |
| nDCG | 考虑排序位置的归一化折损累计增益 |

## 常见挑战

1. **检索失败**：知识库中没有相关内容 → 解决：扩大文档覆盖，优化分块
2. **幻觉**：LLM 编造文档中没有的信息 → 解决：严格的 prompt 约束
3. **延迟**：多步骤导致响应慢 → 解决：缓存、异步、模型优化
4. **冷启动**：空知识库无法回答 → 解决：预置文档 + fallback 策略
