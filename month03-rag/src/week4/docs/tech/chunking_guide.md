# Chunking 策略指南

## 什么是 Chunking

Chunking（分块）是将长文档分割成小段的过程，每个块作为检索的基本单元。
分块质量直接影响 RAG 系统的检索效果。

## 常见策略

### 1. 固定长度分块
- 最简单的策略
- 按固定 token 数切割
- 缺点：可能截断语义单元
- 适用：结构化文本

### 2. 递归分块
- 按分隔符优先级递归切割
- 优先级：段落 → 句子 → 词
- 优点：尽量保持语义完整性
- 适用：大多数场景

### 3. 语义分块
- 基于 embedding 相似度判断边界
- 相邻句子相似度骤降处切分
- 优点：语义边界精准
- 缺点：计算成本高

### 4. 文档结构分块
- 利用文档自身结构（Markdown 标题、HTML 标签）
- 优点：保留文档逻辑结构
- 适用：有明确结构的文档

## 关键参数

| 参数 | 说明 | 推荐值 |
|------|------|--------|
| chunk_size | 每块最大长度 | 256-1024 tokens |
| chunk_overlap | 相邻块重叠长度 | 10-20% chunk_size |

## 最佳实践

1. **根据文档类型选择策略**：结构化文档用结构分块，自由文本用递归分块
2. **chunk_size 不宜太小**：太小丢失上下文，太大检索精度下降
3. **保留元数据**：记录来源、位置、标题等，便于追溯
4. **测试不同的 overlap**：overlap 太小可能漏掉边界信息
