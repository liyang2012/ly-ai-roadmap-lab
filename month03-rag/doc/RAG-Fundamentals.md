# RAG 入门科普：给小白的第一课

> 本文是 month03-rag 的前置阅读材料。如果你完全不知道 RAG 是什么，从这里开始。

---

## 1. 一句话说清楚：什么是 RAG？

**RAG** = **R**etrieval-**A**ugmented **G**eneration（检索增强生成）

用人话说就是：**给 AI 一个"翻书找答案"的能力**。

### 生活类比

想象你在参加一场考试：

| 场景 | 类比 | 效果 |
|------|------|------|
| **没有 RAG** | 闭卷考试：只能靠脑子里记住的东西答题 | 遇到没背过的题就可能瞎编 |
| **有 RAG** | 开卷考试：可以先翻书找答案，再组织语言作答 | 答案准确，有据可查 |

RAG 就是让 AI 从"闭卷考试"变成"开卷考试"。

---

## 2. 为什么需要 RAG？—— LLM 的三个"硬伤"

大语言模型（LLM）虽然很强，但有三个天生的问题：

### 硬伤 1：知识截止

LLM 的训练数据有一个截止日期。比如模型在 2025 年 6 月训练完成，那它不知道 2025 年 7 月发生了什么。

```
你问：2026年世界杯谁赢了？
LLM：（内心OS：我训练数据里没有这个信息……）
```

**RAG 怎么解决**：把最新的新闻文档存到知识库里，AI 先去检索，再回答。

### 硬伤 2：幻觉（一本正经地胡说八道）

当 LLM 不知道答案时，它不会说"我不知道"，而是会编一个看起来很合理的答案。

```
你问：XX公司的退货政策是什么？
LLM（瞎编）：根据我们的政策，30天内可以无理由退货……
（实际上这家公司根本没有这个政策）
```

**RAG 怎么解决**：AI 必须基于检索到的真实文档回答，有据可查，减少瞎编。

### 硬伤 3：不知道你的私有数据

LLM 的训练数据来自公开互联网。你公司内部的产品手册、FAQ、技术文档，LLM 根本没见过。

```
你问：我们公司的 X100 手表防水等级是多少？
LLM：（内心OS：这是什么产品？我从来没见过……）
```

**RAG 怎么解决**：把你的私有文档存入知识库，AI 检索后就能回答了。

## 3. RAG 的工作流程（3 个阶段）

RAG 的完整流程分为 **离线索引** 和 **在线查询** 两个阶段：

### 阶段一：离线索引（Indexing）——只做一次

这一步是"把书放进图书馆"，只需要做一次（或者文档更新时重新做）。

```
你的文档（Word/PDF/网页等）
    │
    ▼
[分块] ← 一本大书拆成若干段落
    │
    ▼
[Embedding] ← 把每段文字变成一串数字（向量）
    │
    ▼
[向量数据库] ← 把这些数字存起来，等待检索
```

**为什么要分块？** 就像一本书不会只有一页纸，一个文档通常很长。我们需要把它切成小段落，这样检索时才能精确找到相关段落，而不是把整本书都扔给 AI。

**什么是 Embedding？** 后面有专门的文档讲解。简单理解：把文字变成"语义指纹"（一串数字），语义相似的文字，指纹也相似。

### 阶段二：在线查询（Query）——每次用户提问时

这一步是"去图书馆翻书找答案"，每次用户问问题时都会执行。

```
用户问题："X100 防水吗？"
    │
    ▼
[Embedding] ← 把问题也变成一串数字
    │
    ▼
[向量检索] ← 在数据库里找和问题"语义最接近"的文档段落
    │  比如找到了：product_faq.md 中的"IP68 级防水"段落
    ▼
[拼接 Prompt] ← 把检索到的文档 + 用户问题组合在一起
    │
    ▼
[LLM 回答] ← AI 基于文档内容生成回答
    │
    ▼
最终回答："X100 支持 IP68 级防水，可在 50 米水深下正常工作……"
```

### 阶段三：生成回答（Generation）

LLM 拿到"参考资料 + 用户问题"后，就像一个"阅读理解高手"一样回答问题。

## 4. 一个具体的例子

假设你有一个电商知识库，里面有 5 篇文档：

| 文档 ID | 内容摘要 |
|---------|---------|
| refund_policy | 退款政策：未发货全额退款，已签收7天内可退 |
| shipping_info | 物流说明：满99元免运费，顺丰速运 |
| coupon_rules | 优惠券规则：每笔订单只能用一张 |
| product_warranty | 保修政策：电子产品1年保修 |
| vip_benefits | 会员权益：钻石会员享85折+免运费 |

### 用户问："买了手机用了一个月坏了怎么办？"

**Step 1 - 检索**：系统在知识库里搜索，找到最相关的 2 篇文档：
- `product_warranty`（保修政策）—— 距离 0.59，高度相关
- `refund_policy`（退款政策）—— 距离 0.72，有一定相关

**Step 2 - 拼接 Prompt**：
```
你是一个电商客服。请根据以下参考资料回答用户问题。

参考资料：
[来源: product_warranty]
电子产品：7天无理由退换，15天质量问题换货，1年保修...

[来源: refund_policy]
退款政策：未发货订单支持全额退款...

用户问题：买了手机用了一个月坏了怎么办？
```

**Step 3 - LLM 回答**：
```
根据保修政策，您的手机购买一个月（在1年保修期内），
如果是质量问题，可以享受保修服务。
请联系客服提交凭证，审核后可寄回维修或换新。
```

## 5. 关键词匹配 vs 语义检索

### 最简单的检索方式：关键词匹配

就像在 Google 搜索一样：你输入什么词，就匹配包含这个词的文档。

**问题**：如果用户的用词和文档不一样，就匹配不到。

```
用户问："什么是不可变的序列？"
文档里有："Python 的元组（tuple）是不可变序列"

关键词匹配：匹配失败！（因为用户的问题里没有"元组"这个词）
语义检索：匹配成功！（因为"不可变的序列"和"元组"语义上是相关的）
```

### 更好的方式：语义检索（用 Embedding）

语义检索能理解"意思"，而不是只匹配"字面"：
- "坏了" ≈ "故障" ≈ "损坏"
- "免邮" ≈ "免运费" ≈ "包邮"
- "不可变的序列" ≈ "元组"

**这也是为什么我们需要 Embedding 模型**——它能把文字变成数字，并且让语义相似的文字在数字空间中"距离很近"。

## 6. 关键参数速查

| 参数 | 含义 | 推荐值 | 为什么 |
|------|------|--------|--------|
| `top_k` | 检索返回多少篇文档 | 2~5 | 太少可能漏掉，太多引入噪声 |
| `temperature` | LLM 的"创造力" | 0.1~0.3 | RAG 要忠于文档，不要发挥创意 |
| `max_tokens` | 回答最大长度 | 300~500 | RAG 回答通常不需要太长 |
| `chunk_size` | 每个文档块的大小 | 200~1000 字符 | 太短信息碎片化，太长多主题混杂 |
