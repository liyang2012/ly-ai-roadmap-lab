# 📊 Week 4 选型对比：Workflow vs Agent

在 AI 系统的落地实践中，最大的分歧往往是：**我们该选择确定性的 Workflow（工作流，如 LangGraph），还是更灵活的 Agent（智能体，如 Agents SDK / Tool-calling）？**

为了给出量化的科学依据，我们在 Week 4 进行了一场**对比实验**。

---

## 🧪 实验设计

我们使用同一个**电商客服需求**（包含 7 个标准用例和 3 个模糊/混合用例），分别编写了两个版本：

1. **Workflow 版 (`workflow_version.py`)**：使用 LangGraph 显式定义状态机，依靠规则路由，零 LLM 依赖。
2. **Agent 版 (`agent_version.py`)**：模仿 Agents SDK 风格，通过 LLM 分析语义进行动态 Tool 选择和回答。

---

## 📊 实验数据对比

每个测试用例运行 5 次，平均指标如下：

| 评估维度 | Workflow 版本 (LangGraph 规则) | Agent 版本 (LLM 驱动) | 选型启示 |
| :--- | :--- | :--- | :--- |
| **标准意图延迟** | **0.02 ms** | 1009 ms | Workflow 胜出 (快 50,000 倍) |
| **标准意图准确率** | **100%** | 100% | 平手 |
| **回答一致率** | **100%** | ~90% (LLM 随机性) | Workflow 更加稳定 |
| **Token 消耗** | **0 Token** | ~1300 Tokens/次 | Workflow 成本极低 |
| **模糊意图准确率** | 0% (走 fallback) | **100%** | Agent 具备强大的泛化理解力 |
| **混合/重叠意图** | **100%** (依靠人工优先级规则) | 0% (产生意图冲突) | **意图冲突陷阱** (见下文) |

---

## 🔍 深度洞察与踩坑记录

### 1. 意图重叠冲突 (Intent Collision)
* **现象**：对于输入 `"已发货的订单能退款吗？订单 ORD20260417001"`，Workflow 版能够准确进行「退款」答复（100% 准确），而 Agent 版会误判为「订单查询」答复。
* **原因**：Agent 的路由策略（不管是 Prompt 还是 if-else 判定）如果先处理了「订单」和「发货」关键词，就会提前截断「退款」意图。
* **解法**：在 Workflow 中我们可以编写硬编码的优先级队列；而在 Agent 中，必须通过极其精细的 System Prompt 约束、少样本提示（Few-Shot）或者结构化 Pydantic 输出限制来规范。

### 2. 边际成本 (Marginal Cost)
* Workflow 版本虽然灵活性差（面对 `"我的东西什么时候到"` 这种没有命中 "物流/快递" 关键词的口语，只能走 Greeting 降级），但其运行成本为 0，且延迟仅为毫秒级。
* Agent 版本极具弹性，能够听懂 `"东西什么时候到" = 物流`，`"这个手机" = iPhone 15 Pro`，但每一次对话都需要消耗 1-2 次 LLM 调用，在百万级日活的系统中会带来极大的 Token 账单与延迟挑战。

## 🎯 工业级选型判定标准 (Decision Tree)

我们总结出以下决策路径：

```
                    【是否需要动态规划步骤？】
                           /         \
                         是           否
                        /             \
            【使用 Autonomous Agent】    【步骤是否固定，仅分支动态？】
                                                /           \
                                              是             否
                                             /               \
                                   【使用 LangGraph】     【使用纯流程引擎】
                                 (即 Workflow 模式)        (如 Spring/Airflow)
```

1. **强控制流优先选择 Workflow**：
   * 财务审批、订单核销、合规性强相关的流程，**严禁使用 Autonomous Agent**，应该用 LangGraph 锁定图结构，即使中间节点用 LLM 润色，路由也必须是确定性的。
2. **多模态/多输入/弱结构优先选择 Agent**：
   * 自由对话、脑暴助手、代码生成，必须发挥 LLM 的非结构化推理能力。
3. **混合架构（Hybrid）是行业终局**：
   * 用 Workflow 搭建骨架（确定骨干节点和边界规则），把 Agent 放在叶子节点中执行局部决策。例如：Joplin 知识同步通过 Workflow 确保数据一致，而冲突内容的智能合并由 Agent 执行。
